# Interview Analyze 스킬

`.claude/interview-logs/` 에 쌓인 인터뷰 로그를 읽고 패턴을 분석한다.
분석 결과를 바탕으로 `/interview` 스킬 개선안을 구체적으로 제안한다.

---

## Step 1: 로그 수집

```bash
# 로그 파일 목록 확인
ls -lt .claude/interview-logs/ 2>/dev/null

# 로그가 없으면 안내 후 종료
# "아직 인터뷰 로그가 없습니다. /interview 를 먼저 사용해보세요."
```

로그가 있으면 모든 파일을 읽는다.

---

## Step 2: 정량 분석

각 로그에서 아래 항목을 추출해 집계한다.

| 분석 항목 | 추출 방법 |
|----------|----------|
| 총 인터뷰 횟수 | 로그 파일 수 |
| 평균 라운드 수 | `rounds_used` 평균 |
| 충돌 발생률 | `conflicts_found: true` 비율 |
| 작업 크기 분포 | `task_size: large/small` 비율 |
| 가장 모호했던 차원 | `가장 모호했던 차원` 필드 빈도 집계 |
| 충돌 발생 지침 | `충돌 발생 지침` 필드 빈도 집계 |
| 핵심 결정 포인트 | `핵심 결정 포인트` 키워드 빈도 |

---

## Step 3: 패턴 분석

아래 관점으로 반복 패턴을 찾는다.

**모호함 패턴**
- 어떤 차원(범위/기술방식/데이터/UX흐름/제약조건)이 가장 자주 모호한가?
- 특정 유형의 요청(인증·알림·통계 등)에서 반복되는 모호함이 있는가?

**지침 충돌 패턴**
- 어떤 POLICY.md 섹션과 자주 충돌하는가?
- 충돌 후 사용자가 주로 어떤 선택을 했는가? (지침 변경 / 방향 수정)

**질문 효율**
- 라운드가 많이 필요했던 요청의 공통점은?
- 1라운드로 끝난 요청의 공통점은?
- 선택지 제시가 효과적이었던 질문 유형은?

---

## Step 4: 개선안 도출

분석 결과를 바탕으로 `/interview` 스킬에 반영할 개선안을 제안한다.

### 출력 형식

```
📊 인터뷰 로그 분석 결과

기간: [첫 로그 날짜] ~ [마지막 로그 날짜]
총 인터뷰: N회 | 평균 라운드: N.N | 충돌 발생률: N%

─────────────────────────
🔍 모호함 패턴 Top 3

1. [차원명] — N회 ([%])
   반복 사례: [예시]

2. [차원명] — N회
   반복 사례: [예시]

3. [차원명] — N회
   반복 사례: [예시]

─────────────────────────
⚠️ 지침 충돌 패턴

가장 많이 충돌한 지침: POLICY.md §N ([섹션명]) — N회
사용자 선택 경향: [지침 변경 N회 / 방향 수정 N회]

─────────────────────────
⚡ 질문 효율 분석

라운드 많이 필요한 요청 유형: [패턴]
1라운드로 끝난 요청 유형: [패턴]

─────────────────────────
✅ /interview 스킬 개선 제안

[제안 1] 우선순위: 높음
현상: [반복 패턴]
제안: [구체적 개선 내용]
적용 위치: SKILL.md Step N

[제안 2] 우선순위: 중간
현상: [반복 패턴]
제안: [구체적 개선 내용]
적용 위치: SKILL.md Step N

─────────────────────────
지금 /interview SKILL.md 에 개선안을 바로 반영할까요?
```

---

## Step 5: 스킬 자동 개선 (선택)

사용자가 반영을 요청하면:
1. `.claude/skills/interview/SKILL.md` 를 읽는다
2. 제안한 개선안을 해당 위치에 직접 적용한다
3. 변경 내용을 diff 형태로 보여준다
4. 커밋 여부를 확인한다

---

## 실행 원칙

- 로그가 3개 미만이면 "데이터가 부족해 패턴 분석이 어렵습니다"라고 안내한다.
- 개선안은 반드시 **구체적인 SKILL.md 위치**를 지목해야 한다. 추상적 제안은 하지 않는다.
- 사용자 확인 없이 SKILL.md를 수정하지 않는다.
