# Interview 스킬

모호한 요청을 받으면 **구현하지 않는다.**
먼저 결정이 필요한 것들을 모두 꺼내놓고, 사용자와 함께 하나씩 확정한다.

---

## Step 1: 컨텍스트 스캔

구현하기 전에 이미 결정된 것을 파악해서 불필요한 질문을 제거한다.

```bash
# 앱 정책 확인 — 이미 결정된 방향 파악
cat habit-tracker/docs/planning/POLICY.md 2>/dev/null

# 기존 도메인 모델 확인 — 이미 있는 구조 파악
find habit-tracker/src/main/java -name "*.java" 2>/dev/null | head -30

# 기존 API 계약서 확인
cat habit-tracker/docs/api/endpoints.md 2>/dev/null
```

스캔 결과를 바탕으로 **이미 결정된 사항은 질문에서 제외**한다.

---

## Step 2: 요청 분해

요청을 아래 5개 차원으로 분해해서 각 차원에서 모호한 것을 찾는다.

| 차원 | 물어야 할 것 |
|------|------------|
| **범위** | 이번에 만들 것과 만들지 않을 것의 경계 |
| **기술 방식** | 어떤 방식으로 구현할지 (A vs B vs C) |
| **데이터** | 저장할 정보, 필수/선택 여부 |
| **UX 흐름** | 사용자가 어떤 순서로 이 기능을 사용하는지 |
| **제약 조건** | 쓰면 안 되는 것, 지켜야 할 기준 |

각 차원에서 모호한 항목을 리스트업한다.
**이미 POLICY.md나 기존 코드에서 답이 나온 항목은 제외한다.**

---

## Step 3: 질문 우선순위 정렬

모호한 항목들을 결정 트리 순서로 정렬한다.

- **상위 결정이 하위 결정을 결정한다.**
  예: "소셜 로그인 쓸 건지"가 결정돼야 "어떤 소셜인지"를 물을 수 있음
- 상위 결정부터 먼저 묻는다.
- 답에 따라 불필요해지는 하위 질문은 건너뛴다.

---

## Step 4: 사용자 인터뷰

**AskUserQuestion 도구를 사용해서 질문한다.**

질문 작성 원칙:
- 오픈 질문 금지 → 반드시 선택지를 제시한다
- 선택지가 없는 경우(자유 입력)는 "Other" 옵션을 활용한다
- 한 번에 최대 4개 질문 (AskUserQuestion 제한)
- 4개를 초과하면 **라운드를 나눠서 순차적으로** 질문한다
- 첫 라운드에서 상위 결정 질문, 다음 라운드에서 하위 결정 질문

질문 전에 아래 형식으로 컨텍스트를 출력한다:
```
📋 요청 분석: [사용자 요청 한 줄 요약]

이미 결정된 것: [POLICY.md/코드에서 파악한 내용]
확인이 필요한 것: [총 N가지]

아래 질문에 답해주시면 구현 방향을 확정하겠습니다.
```

---

## Step 5: 요구사항 확정 및 요약

모든 질문의 답을 받으면 아래 형식으로 정리해서 출력한다.

```
✅ 확정된 요구사항: [기능명]

범위
- [결정 사항]

기술 방식
- [결정 사항]

데이터
- [결정 사항]

UX 흐름
- [결정 사항]

제약 조건
- [결정 사항]

─────────────────────────
이 내용으로 진행할까요?
→ "응" 또는 "맞아" → /plan 또는 /backend-dev 등 다음 단계로 연결
→ 수정 요청 → 해당 항목만 다시 질문
```

---

## 실행 원칙

- **구현하지 않는다.** 이 스킬의 출력은 항상 질문이거나 요약이다.
- **추측하지 않는다.** 모르면 질문한다. "아마 이렇게 원하시겠지"는 없다.
- **유사 서비스를 레퍼런스로 활용한다.** "카카오처럼? 토스처럼?" 같은 선택지는 설명 비용을 줄인다.
- **이미 결정된 건 묻지 않는다.** POLICY.md와 기존 코드가 이미 답을 갖고 있을 수 있다.
- **사용자가 확정하기 전까지는 다음 단계로 넘어가지 않는다.**
