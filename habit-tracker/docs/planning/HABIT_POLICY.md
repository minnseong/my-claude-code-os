> **연관 파일**: `POLICY.md` (공통 정책)

## 1. 루틴 CRUD 정책

### 1-1. 생성

| 항목 | 정책 |
|------|------|
| 이름 | 필수, 1~50자 |
| 요일 | 최소 1개 이상 선택 필수 |
| 시작일 | 생성 당일 기준 |

### 1-2. 수정

- 이름, 요일만 수정 가능
- 기존 체크 히스토리는 보존 (수정 시 삭제 금지)

### 1-3. 삭제 (Soft Delete)

- **Hard delete 금지** — 데이터베이스에서 행을 지우지 않는다
- `active = false` 처리만 허용
- 삭제된 루틴은 목록에서 숨겨지지만 체크 히스토리에는 계속 표시된다
- UI에서 "삭제" 표현 금지 → "그만하기"로 표시 (`POLICY.md §3-3` 참조)

---

## 2. 체크 정책

### 2-1. 날짜 제약

| 규칙 | 내용 |
|------|------|
| 미래 날짜 체크 | **절대 금지** |
| 허용 범위 | 오늘 포함 과거 날짜만 허용 |
| 하루의 경계 | 자정(00:00) 기준 — 자정이 지나면 다음 날로 전환 |
| 체크 취소 | 당일 체크에 한해서만 허용 |

### 2-2. 요일 필터링

- 루틴에 지정된 요일에만 체크 가능
- 예: 월·수·금 루틴은 화요일 화면에 표시되지 않는다

### 2-3. 중복 체크 방지

- 동일 루틴 + 동일 날짜 조합은 한 번만 체크 가능
- DB 레벨 unique 제약 필수: `(habit_id, check_date)`

---

## 3. 날짜 표시 형식

| 상황 | 표시 형식 |
|------|---------|
| 오늘 | "오늘" |
| 어제 | "어제" |
| 이번 주 이내 | "M월 d일 (요일)" |
| 그 이전 | "YYYY년 M월 d일" |

---

## 4. 히스토리 조회 정책

- 기본 조회 범위: **최근 30일**
- 삭제된 루틴(`active=false`)의 히스토리도 포함 (히스토리는 영구 보존)
- 날짜 역순 정렬 (최신 → 오래된 순)
- 빈 히스토리 시 Empty State 필수 (`POLICY.md §3-2` 참조)

---

## 5. 통계 정책

| 기간 | 기준 |
|------|------|
| 단기 | 최근 7일 |
| 중기 | 최근 30일 |

- 완료율 계산: `(체크한 날 수) / (루틴이 스케줄된 날 수) × 100`
- 삭제된 루틴은 통계에서 제외
- 통계 수치는 0% ~ 100%로 표시, 소수점 없음
